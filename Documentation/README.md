# Development Documentation

当前为报告写作提纲；最终交付文件名必须为 `Development_Documentation.pdf`，目前尚未生成。`evidence/` 预留真实运行记录，不存放虚构截图或测试结果。

## 格式

A4 单栏、11 pt 可读正文字体、编号标题、页码、统一图注和 IEEE 引用。建议正文 12–18 页，不含封面、目录、参考文献和附录。

## 必备章节

1. 文档控制与执行摘要：版本、日期、成员/学号、修订记录、范围、成果和限制。
2. 需求分析：相关方、假设、约束、功能/非功能需求、验收标准、稳定需求 ID 和追踪矩阵。
3. 系统架构：客户端、服务器、TCP、题库访问、部署、职责、接口和信任边界。
4. 详细设计：模块、数据结构、状态模型、并发、同步、计时、错误与关闭设计。
5. 应用层协议：实际分帧、编码、消息字段、关联规则、事件、错误、兼容性、交互过程及示例。
6. 数据设计：强制题库 schema、内存实体、可变状态所有权、校验、答案保密及生命周期。
7. 实现记录：开发环境、源码布局、重要算法、标准库选择、权衡和问题解决。
8. 部署与操作：官方镜像中的精确命令、配置、启动输出、正常关闭、日志和资源假设。
9. 验证与确认：策略、环境、需求映射、可重复用例、预期/实际结果、异常/计时/并发、缺陷和终端证据。
10. 可靠性与安全：输入校验、保密、竞争条件、断连、范围内的拒绝服务风险、日志和恢复。
11. 项目管理与贡献：分工、里程碑、仓库记录、评审、每人职责及合计 100% 的贡献比例。
12. 限制、未来工作与参考文献：基于证据的限制、改进、结论和一致引用。

在最终报告中按学校要求引用实际使用的 AI 工具，并说明用途。成员须理解、审查并验证采用的内容。提交的图片、图表、截图和其他视觉证据应基于本组的实现、实验或分析，可用常规软件制作。详见 [LMO 任务书第 8 页](https://core.xjtlu.edu.cn/mod/assign/view.php?id=37456)。

截图只作支持材料，不能替代测试过程、解释和结果表；不要粘贴完整源码。每项已声称满足的需求必须映射到设计和验证活动。所有提交用命令和结果来自官方 Docker 镜像，视频也必须来自该环境。
