# 测试计划

当前目录仅为规划，尚无测试用例或测试结果。采用 Python 标准库 `unittest`；增加用例后，在官方 Docker 镜像的 `Codes/` 目录运行：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

零条测试不代表系统通过验证。`unit/` 放题库校验、协议编解码和计分测试；`integration/` 放客户端与服务器配对流程、并发和故障测试；`fixtures/` 放测试专用题库或消息样本，客户端运行代码不能借此绕过网络读题。

| 测试 ID | 计划覆盖 |
| --- | --- |
| T01 | 缺失/空/超限文件，UTF-8/JSON 错误，全字段类型和边界，额外字段、重复 ID、非法 options；失败不监听 |
| T02 | 合法题库启动、指定端口、SERVER_READY 顺序、Ctrl+C 资源释放 |
| T03 | 多人登录、重复 ID、显示名及会话规则 |
| T04 | 目录、创建、加入、成员列表、准备、开赛、离开 |
| T05 | 题序、题目关闭、正确/错误/缺失/迟到/重复答案、计分、最终排序 |
| T06 | 至少 10 客户端和 2 个同时运行的房间，事件/答案/计时/计分隔离 |
| T07 | TCP 分片、合并、长度限制、非法 UTF-8/JSON/字段与未知消息 |
| T08 | 大厅/答题中断连，慢客户端，房主离开，错误输入不影响其他会话 |
| T09 | 目录不泄露题目或选项，开放题目不泄露答案，客户端不读取题库 |

每项用例应记录环境镜像及标签、命令、输入、预期结果、实际结果、日期、对应需求和证据路径。正式证据保存在 `Documentation/evidence/`，只有真实运行后才能填写结果。
